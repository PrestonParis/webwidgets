# WebWidgets UI

## Concise Description

- The interface adapts based on insights generated by ML models and AI
- Users can extensively customize the UI using an array of features

## Platform

- Dashboard — Widget grid and free canvas with drag-and-drop layout, scenes, folders, and widget bucket
- Search — Global search bar and widget catalog with suggestions
- Onboarding — Multi-step setup flow covering goals, integrations, and initial workspace generation
- Settings — Profile, appearance, integrations, and plan management
- Billing — Stripe subscription management with checkout and customer portal
- Import / Export — Data import and export pipeline
- Notifications — Notification bell, status dot, and alert system
- Integrations — Integration catalog for Google, Microsoft, GitHub, Linear, Slack, and more
- Admin — Internal admin panel covering users, feature flags, audit logs, metrics, ML, and background jobs
- Feedback — In-product user feedback
- Help — In-product help system

## Customization Features

- Users can customize the widget display, the page display

### Widget Customization

- Free canvas — Move and overlap widgets freely, or snap to a grid.
- Widget bucket — Lesser-used widgets retract to a side icon rather than cluttering the grid.
- Cropping — Crop a widget to extract only the context needed; display adapts accordingly.
- Weave — Multiple widgets of the same class (inboxes, calendars) merge into a unified view.
- Folders — Moveable, styleable containers for personal organization.
- Pinning — Lock a widget's position so it survives layout regeneration.
- Free movement — Move widgets across the canvas with custom placement; overlap allowed.
- Snap rules
  - Free movement
  - Grid snapping
  - Edge magnetism
  - Smart alignment guides
  - Proximity grouping suggestions
- Freezing / pinning modes — Fixed placement with distinct pin behaviors.
  - Viewport pinned — stays on screen during scroll
  - Canvas pinned — fixed relative to workspace
  - Anchor pinned — follows another widget or object

# 6. Cross-Widget Intelligence (Weave)

Widgets should not operate independently.

The richer the widget graph becomes, the smarter the workspace becomes.

Widgets should share:

- context
- actions
- insights
- predictions
- workflows
- priorities
- recommendations

This is one of the core differentiators of WebWidgets.

### Visibility

- Hide — Widget hidden from view but still loaded.
- Low-profile — Privacy-catered minimal display mode.
- Scheduled visibility — Set time windows for when a widget appears or disappears.
- Unpresent — Widget not rendered at all; add back from home page or settings.
- Widget states — Explicit runtime lifecycle states beyond visible/hidden. Essential for performance at scale.
  - Active — fully interactive
  - Passive — displays updates, no interaction
  - Dormant — in memory but not updating
  - Suspended — fully paused, zero compute
  - Archived — layout + state saved, not loaded

### Organization

---

### Widget Relationships

- Relationship graph — Generalized system letting the engine reason about interactions. Glueing and weaving are specific instances of this.
  - Independent
  - Attached (glued)
  - Embedded (foldered)
  - Merged (woven)
  - Dependent — one requires another
  - Reactive — one responds to another
  - Mirrored — state sync
- Glueing — Widgets stick together without shared context or UI overlap. A visible connector appears between them.
- Weaving — Widgets act as one unit for movement, with UI overlap and shared insights/context.

---

### Display

- Cropping — Custom crop of a widget to extract necessary context; widget display adapts accordingly.
- Styling — Color, size, opacity, brightness. Copy styling from another widget or folder.

### 2. Hypermodern UI

After the feature surface exists, heavily improve the interface.

The UI should feel premium, dense, fast, customizable, and suitable for a personal OS-style product.

Refinement after this stage should focus on:

- Design tokens
- Responsive layouts
- Dashboard density
- Widget resizing
- Empty states
- Loading states
- Page-level consistency
- Motion and transitions
- Accessibility
- Visual hierarchy
- Component reuse
- Removing ugly agent-generated stacking patterns

Agents should avoid generic vertical-card layouts unless the use case truly calls for them.
